V2.19.0 IMPLEMENTATION AUDIT

BASELINE
- Forked from the V2.18.4 worker, preserving BTC next-move scenario engine, BTC/ETH historical context, existing three entry families, anti-flip/cooldowns, paper outcome accounting, structural risk and Telegram delivery.
- CLEAN_START_ID remains unchanged. Existing paper trades and state are not intentionally reset.

SIX UPGRADE AREAS
1. Universe-wide scan: every active perp returned by metaAndAssetCtxs is placed in the global historical-memory refresh queue. Backfill is staged in batches to control runtime/API load.
2. Historical levels: separate 15m and 1h Hyperliquid perp candles; pivot clusters and repeated independent interactions are extracted.
3. Reaction quality: support/resistance touches, successful reactions, success rates, average follow-through, role and recency are retained per level.
4. Role reversal: the closest historical level is evaluated even after price crosses it; two completed closes beyond the former level are required for confirmed break/reversal.
5. Live decision: current completed candles are used with historical context. Historical reaction aligns/penalizes candidate score; conflicting higher-timeframe reaction can block. A coin cannot emit a new paper signal until both timeframe maps are ready.
6. Out-of-sample validation: a walk-forward historical reaction backtest rebuilds levels from prior candles only, tests later candle outcomes with conservative same-candle SL handling, deducts estimated round-trip costs, and records resolved win rate, average net R and profit factor. Backtest expectancy affects candidate conviction only after at least 30 resolved samples.
7. Persistent state: workflow commits the state JSON after each run, preserving the historical memory and paper cohort across ephemeral GitHub runners.

DATA / DEFAULTS
- 15m lookback: 180 days.
- 1h lookback: 730 days.
- 5 coins per run, refresh after 24h.
- Hyperliquid public candleSnapshot data; no Binance spot substitution for perp-level memory.
- All stored candles are completed candles only.

VALIDATION BOUNDARIES
- Syntax check and synthetic tests are included in this package.
- No live API scan or full GitHub Actions execution has been performed in this environment. The walk-forward engine itself is implemented and synthetic-tested; real per-coin performance metrics will only exist after the GitHub workflow backfills actual Hyperliquid history.
- Hyperliquid API retention/rate limits may result in shorter history for newly listed or unavailable markets; warnings are logged and prior cache is retained.
- This is not a predictive guarantee. Historical levels are contextual evidence and must be evaluated on an out-of-sample paper cohort.
